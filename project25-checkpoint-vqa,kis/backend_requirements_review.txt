BACKEND AIC 2026 REQUIREMENTS REVIEW
====================================

Verdict: PARTIALLY COMPLIANT

The KIS foundation is solid, but the backend does not yet meet the full AIC
Tracking specification. The main gaps are VQA count logic, TRAKE alignment,
tracking/logging, and the submission ZIP exporter.

WHAT IS CORRECT
---------------
1. FAISS uses normalized 512D CLIP vectors with IndexFlatIP, which supports
   cosine-similarity search.
2. FAISS index and metadata are internally consistent:
   - Index dimension: 512
   - Indexed vectors: 7,800
   - Metadata rows: 7,800
3. Metadata correctly separates keyframe_id (JPEG filename) from frame_id
   (original video frame), avoiding a common submission-mapping error.
4. KIS results include video_id, frame_id, thumbnail URL, and score.
5. VLM answers are capped at 100 characters.
6. Application startup succeeded in the current environment.

REQUIREMENT COVERAGE
--------------------
1. Vector indexing and metadata
   Status: PARTIAL
   - Implemented: .npy loading, FAISS Flat IP index, vector-to-video/frame
     metadata mapping.
   - Missing: timestamp and image_path in metadata.
   - Note: the specification requires a score in [0, 1], but raw cosine
     similarity is currently returned in its natural [-1, 1] range.

2. KIS pipeline
   Status: PARTIAL
   - Implemented: text encoding, FAISS search, candidate IDs, score, image URL.
   - Missing: required POST /api/v1/search/kis endpoint. The code exposes only
     generic POST /api/v1/search.
   - Missing: required latency_ms in the response.
   - Response field differs from spec: thumbnail_url instead of image_url.
   - Performance target (< 1 second) is not measured or guaranteed. Cold model
     loading and external translation may exceed the target.

3. Objects JSON / Faster R-CNN indexing and count queries
   Status: NOT IMPLEMENTED
   - No Object JSON index or O(1) lookup by (video_id, frame_id) was found.
   - No count-question detection or confidence-threshold filtering exists.
   - Required GET /api/v1/objects/count endpoint is missing.

4. VQA pipeline
   Status: PARTIAL
   - Implemented: retrieves KIS candidates and sends candidate images to Gemini.
   - Missing: separate POST /api/v1/search/vqa endpoint and specified payload.
   - Missing: use_vlm option, source field, vlm_raw_log, and one selected result
     matching the required response contract.
   - Missing: count-query branch based on Faster R-CNN JSON.
   - Missing: VLM timeout/rate-limit logging and fallback behavior.
   - Current behavior invokes the VLM for all five candidates, which is slow and
     costly; retrieve candidates first, then choose/rerank a small set.

5. TRAKE temporal alignment
   Status: NOT IMPLEMENTED
   - The current TRAKE service performs a single KIS search only.
   - Missing: sub_queries input, per-event retrieval, same-video constraint,
     strictly increasing timestamps, DTW/temporal selection, and the required
     aligned_sequence output.

6. Tracking, logs, and visualizer data
   Status: NOT IMPLEMENTED
   - No persistent query history, raw AI output log, final-output log, or human
     edit history exists.
   - No query_id, per-stage latency, heatmap/timeline score data, or tracking
     logs endpoint exists.

7. Export and submission package
   Status: PARTIAL / INCORRECT
   - Existing endpoint returns CSV only: POST /api/v1/export/csv.
   - Missing: specified POST /api/v1/export/submission endpoint, validation,
     submission directory, ZIP generation, and downloadable ZIP URL.
   - Current CSV construction is not safe for answers containing commas or
     double quotes. It must use csv.writer (or equivalent) so quotes become
     doubled and fields are properly quoted.
   - VQA answers must be validated to 100 characters at export time too.

CRITICAL CORRECTNESS ISSUES
---------------------------
1. Invalid FAISS result IDs:
   If top_k is larger than the index size, FAISS may produce index -1. The
   current condition accepts -1 and reads the last metadata item. Require:
       0 <= idx < len(metadata)
   and validate/bound top_k before search.

2. Score normalization:
   Convert returned cosine score using:
       normalized_score = max(0.0, min(1.0, (cosine_score + 1.0) / 2.0))
   Preserve raw cosine separately in logs if needed.

3. Deployment dependencies:
   requirements.txt omits several runtime dependencies directly imported by the
   app, including FastAPI, Uvicorn, NumPy, FAISS, Torch, SentenceTransformers,
   Google GenAI, and python-dotenv. A clean deployment may fail.

RECOMMENDED MINIMUM IMPLEMENTATION PLAN
---------------------------------------
1. Add separate typed endpoints exactly matching the specification:
   /api/v1/search/kis
   /api/v1/search/vqa
   /api/v1/search/trake
   /api/v1/objects/count
   /api/v1/tracking/logs
   /api/v1/export/submission

2. Add ObjectsStore:
   Load Faster R-CNN Object JSON during startup into a dictionary keyed by
   (video_id, frame_id), with confidence filtering and class normalization.

3. Add a trace store:
   SQLite is sufficient. Store query_id, input, candidates, raw VLM output,
   object-count evidence, final output, edit history, stage timings, and errors.

4. Implement TRAKE:
   Search separately for every sub-query, group candidates by video_id, and
   select a sequence with strictly increasing timestamps/frame IDs.

5. Implement reliable CSV and ZIP export:
   Use Python csv.writer, validate rows and answer length, write files beneath
   submission/, and create the required ZIP archive.

6. Add tests:
   Test CSV escaping, score normalization, top_k bounds, object counts,
   temporal ordering, endpoint schemas, and exporter validation.

CONCLUSION
----------
The existing work is a good KIS prototype, with correct FAISS/metadata mapping.
It is not yet a complete AI Tracking backend under the supplied AIC 2026
specification. Prioritize the critical correctness fixes, Object JSON count
support, TRAKE alignment, tracking storage, and compliant ZIP export before
claiming full compliance.
